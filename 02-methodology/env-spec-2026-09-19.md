## 1. Problem, formally

Distributed SDVN control plane with K controllers, each owning a disjoint set of
data-plane switches/RSUs. Vehicles move and re-associate; association changes push
demand between controller domains. A controller whose service demand exceeds its
service rate is *overloaded* (queue growth → response latency → packet loss).
The agent decides **when and where to migrate a switch's control relationship**
(binary switch migration, cf. B0–B6) so that load is balanced across controllers
without paying more migration cost than the imbalance justifies.

Decision problem = POMDP `⟨S, A, P, R, Ω, O, γ⟩`:

- **Partial observability is structural, not incidental.** Each controller sees
  only its own queue and arrival statistics, plus *optional* neighbour telemetry
  that may be dropped (network delay, sync lag). No agent ever sees the global
  load vector — that is what makes a recurrent encoder useful rather than
  decorative (LR-43/45; and DRQN ≠ seen in any of the 22 T1 full texts: 0 hits).
- **Non-stationarity comes from mobility.** Handovers move load between domains
  on a timescale (seconds) comparable to the controller's queue relaxation time,
  so the load process is neither stationary nor Markov in the observation.

## 2. Environment (tier 1, `sim/sdvn_env.py`)

| element | spec |
|---|---|
| tick | 1 simulated second; episode = 3600 ticks (1 sim-hour); scenario matrix over density × K × mobility × masking |
| vehicles | positions from a SUMO trace (TraCI/FLOWS dump) or, when absent, a built-in synthetic mobility model (configurable speed distribution, road loop) |
| association | nearest RSU with 10 % hysteresis; each handover emits a registration burst to the new controller |
| demand | Poisson packet-ins per RSU with rate λ ∝ (local vehicle count) × (per-vehicle control-message rate); burst multiplier on handover |
| controllers | M/M/1-style queue, service rate μ per tick, finite capacity; queue length = load signal, response latency = queue/μ (p95 tracked) |
| actuator | migrate switch s from controller i to j; cost = C_msg + C_sync × (state to transfer), plus a cooldown before the same switch may move again |
| overload | queue > threshold for ≥ τ ticks → overload event recorded with its onset time (used for lead time) |
| randomness | seeded numpy Generator; every run reproducible from `config.seed` |

## 3. Observation, action, reward (as implemented)

- **Observation (per controller, agent-side aggregate):** window of k = 8 ticks
  over `[queue_len, arrival_rate_ewma, service_rate, overload_flag,
  vehicle_count_zone, handover_in_rate, ticks_since_last_migration]`, concatenated
  across controllers with a *telemetry mask vector*; masked neighbour blocks are
  zeroed and flagged in the mask (train-time dropout p ∈ {0, 0.15, 0.3}).
- **Action (discrete):** `0 = no-op`; otherwise `(s, j)` for the `S_cand = 3`
  most-loaded switches of the most-loaded controller and every other controller
  `j`, i.e. `1 + 3·(K−1)` actions (K = 3 → 7). Fractional variant
  `(s, j, f ∈ {0.25, 0.5, 1.0})` is an **ablation**, not the primary space, so the
  agent stays comparable with B0–B6 (LR-60 §4).
- **Reward (per tick):**
  `r = −[ w_j·(1 − Jain(load)) + w_c·migration_cost + w_o·overload_ticks + w_r·re-migration ]`
  with `w_j = 1.0, w_c = 0.05, w_o = 0.5, w_r = 0.5` (config-tunable; reported in
  the thesis as the single scalarisation used for all agents).

## 4. Metric contract (unchanged from LR-50, plus mobility additions)

- **Primary:** Jain's fairness index over controller load; p95 packet-in response
  latency.
- **Guard-rails:** migrations per slot and cumulative migration cost;
  re-migration within 2T (instability); overload-event count.
- **Novel:** **lead time** — seconds before an overload event at which the agent
  acts (proactive claim, falsifies B0–B2); **handover-induced migration rate**
  (migrations that immediately follow a handover) and transient imbalance during
  handover storms (the mobility-specific columns no T1 paper reports).
- Note from the full-text probes: Jain is reported by only 3 of 22 T1 papers and
  no paper reports the mobility columns — so we report a superset and say so.

## 5. Baselines (interface fixed; implementations in `sim/baselines.py`)

| id | policy | status |
|---|---|---|

## 6. Two-tier validation

Tier 2 = Mininet-WiFi + Ryu vignette: one topology (3 controllers, 15 RSUs), one
trained policy, replay one scenario, show *direction* agreement on Jain /
migrations / p95 latency. Deliverable: the "emulation vs simulation" fidelity
chapter promised in the approved proposal. The Ryu-side policy port reads the
same config, so no retraining is implied.

## 7. What is frozen vs open

Frozen: tick semantics, queue model, observation content (window k=8), action set
(7 actions at K=3), reward weights' *form*, metric contract, baseline list.
Open (ablation axes only): Double/Dueling on/off, telemetry dropout rate,
mobility parameters, fraction-vs-binary action space, replay sampling (sequences
vs frames), LSTM hidden size.
